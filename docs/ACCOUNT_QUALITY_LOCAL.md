# 分组账号质量管理与自动调度

更新：2026-10-19。工作分支：`codex/manxue-candy-api`。

## 使用入口

当前本机前端：`http://127.0.0.1:3000/admin/accounts`，后端：`http://127.0.0.1:8080`；启动脚本 `.dev/start.py`。下文 Windows 备份及旧验收记录为此前部署历史。远程服务器未更新。

账号管理默认按分组卡片展示，支持搜索、平台/状态筛选、卡片折叠、每组独立分页与组内排序。未分组账号单列；账号同时属于多组时分别展示。同一账号跨组勾选只计一次，批量操作复用原有管理逻辑。右上角可返回原始列表使用原有完整列与筛选。

## 账号调度与容量

分组卡片增加“容量”和“调度”列，调度开关调用原账号列表的同一接口。关闭后该账号停止接收新调度，已建立请求继续按原有网关行为处理；这是账号整体状态，会同步到该账号所属的全部分组。保存期间同一账号在各卡片的开关一起禁用，失败保留原状态；成功后刷新相关分组的可用账号数、排名及份额，并同步原始列表。

容量复用原列表的显示组件，展示当前并发/并发上限，以及已配置的API Key额度、Anthropic窗口费用、会话数和RPM限制。数据按当前页账号批量查询，容量响应不包含账号凭据。读取失败保留未知值，显示“—”；可用页面刷新按钮更新运行时容量。

## 巡检设置

糖果检测自动读取每个 API Key 账号已保存的上游 Base URL 和 API Key，使用该账号的模型映射；无需另填地址、配置本系统公网访问或生成检测 Key。删除旧共享地址输入和专用检测中转接口。账号编辑页仍是上游配置的唯一来源，修改后下次检测读取新配置。

每组的“巡检设置”分别保存：

- 请求模型、推理程度、服务档位和接口协议；使用请求模型名，账号映射仍由现有上游适配器处理。
- 默认每 15 分钟巡检，允许 5–1440 分钟；最多两个账号同时测试，轮次不重叠。
- 每日检测额度、每轮账号上限。一个远端糖果任务计一个额度，本地附加复核按请求计，不是费用上限；检测消耗上游模型额度。
- 可选的 ModelTrace 异常复核、短/中/长合成上下文检查。
- 质量/首字/缓存/稳定性四个评分权重，默认 40/25/15/20。
- 调度模式：手动、仅观察、自动质量加权。自动调度与付费巡检使用独立开关。

新组的自动巡检和自动质量调度默认不开启；显式设置模型后才允许巡检或自动模式。验收保留用户已经保存的分组模型、手动检测历史和账号数据。

糖果检测支持 OpenAI、Kimi、Zhipu、DeepSeek、OpenCode Go 的 API Key 账号，上游须支持公网 HTTPS Responses。推理程度为 `low/medium/high/xhigh/max/ultra`，服务档位为默认、`priority/ultrafast`；旧配置 `none/unspecified/flex` 需用户修改。OAuth 账号没有可直接提交的普通上游 API Key，因此糖果按钮禁用并说明原因，不将 OAuth token 当作 API Key；原有本地指纹和上下文检查继续可用。

ModelTrace、上下文检查保留原有 Responses、Chat Completions、Messages、generateContent 适配。原生 Gemini 要求 `unspecified` 推理程度和默认服务档位。

## 满血 API 糖果检测

按 [满血 API 文档](https://manxue.ai/api)向固定的 `https://manxue.ai/api/v1/tests` 提交 `benchmark=candy`，包含该账号的上游地址、已保存的 API Key、映射后的模型、推理程度与档位。满血直接调用该上游，不经过本系统公网入口；测试对应账号所保存的那组上游凭据。手动确认与自动巡检设置明确说明凭据提交和额度消耗。

上游 URL 复用账号适配器的 Responses 规则：例如 `https://codekey.example/` 对应 `/v1/responses`，已有 `/v1`、其他版本和反代路径保留；已带 `/responses` 时不重复追加。交给满血的 `base_url` 去除末尾 `/responses`，由满血自行补齐。不拼接任何本系统专用路径。不满足公网 HTTPS、缺少 Key、不可调度或参数不支持时，预检错误计零额度，不提交任务。

后台每 3 秒查询任务，最长等待约 10 分钟。任务 `succeeded` 只表示执行完成，必须根据 `candy.status=passed/incorrect/error` 保存判定；不使用本地固定答案判题。远端检测异常立即对同一账号追加最多 3 次重试，取得 passed/incorrect 即停止；每次新检测使用独立幂等键，保留各次结果并计入额度。取消、账号配置变更或未发出请求的本地预检错误不追加任务，证据写入失败也停止重试。每账号预留最多 4 个糖果任务，成功完成整轮后释放未用额度。错误不会当成题目答错。

429/503 按 `Retry-After` 退避，最多尝试三次，同一提交沿用幂等键，避免重复创建付费任务。查询失败、超时、取消或正常服务停止时尽力发送远端 DELETE；本机突然终止时远端可能继续运行到超时。满血任务保留约 1 小时，404 作为失效错误记录。不会自动公开到社区，不将 API Key 或远端任务读取凭证保存到证据。

满血结果使用独立标识 `candy-manxue-v1`，原本地糖果和变式结果仍可查阅，但不影响新糖果评分。上下文失败仍会作为不一致证据展示。

ModelTrace 完全本地运行，随程序嵌入参考库、Go 算法与 MIT 许可，保存库 SHA-256、预期参考模型、三个挑战及回答、首位候选与相对支持度。三份有效输出才做完整归因，缺失或无法解析保持 unknown。0.8 的候选判定线是本地保守显示规则，未被宣传为身份认证；不在参考库的模型不能指定为参考。

上下文检查使用随机生成的合成记录，分别测试约 1K 字符、中等长度和配置的长长度（4K–128K 字符），由程序保存标准答案。测试不使用或上传真实用户内容。

糖果结果保存满血来源、远端状态、请求模型、回答摘要与总耗时；本地复核额外保存题库版本或题面和标准答案。结果保留协议/请求模型/上游映射模型/推理/档位与消耗额度。回答摘要只帮助核对本机归档一致性，不能证明上游身份。历史生成内容只以文本展示，不执行模型返回的 HTML 或代码。

同条件账号跨组的近期满血糖果结果可以在定时巡检中复用 15 分钟，复用记录不增加独立样本、不能链式延长有效期。手动重测始终产生新的测试请求。

## 真实业务指标与评分

- 列表的首字、缓存和记录成功率统一统计滚动最近 24 小时、当前分组下账号的业务流量，默认包含全部被调用模型、推理程度、档位和接口。业务模型筛选使用独立的 `metrics_model` 参数，不继承巡检设置；账号修改凭据也不会抹掉窗口内的业务记录。聚合表现反映真实流量组合，不代表跨模型公平能力比较。
- 首字使用网关已有 `first_token_ms`，展示 P50/P95。评分兼顾中位数与尾部延迟，至少 30 个有效样本才参与。历史不同透传路径的计时语义不完全相同，不能当作供应商身份认证。
- 缓存使用最近 24 小时归一化后的 `SUM(cache_read)/SUM(input+cache_create+cache_read)`，默认汇总账号全部被调用模型，按 token 总量加权，不平均各模型的百分比。该指标是 token 读取占比，不是命中请求比例；仍依赖上游 usage。至少 30 个请求且有输入用量才参与评分，无输入用量显示未知。
- 稳定性使用已记录的成功用量与去重错误，排除业务限制、客户端错误及同账号最终成功的重复错误。错误日志关闭或档位/协议覆盖不明时不推断为完美稳定。
- 新增错误条件字段只保存推理程度和服务档位，不恢复已删除的错误请求体列。历史错误缺少条件时明确降低覆盖可信度。
- 能力题使用最近 1 小时独立满血糖果结果，至少 3 个有效结果才参与。指纹证据独立展示，不把候选支持度当“智商”。
- 列表标明“请求 / 有效首字 / 成功 / 失败”的实际含义，缺失项不记零分；点击评分可查看当前业务筛选范围的分量、样本数和权重。自动调度继续使用匹配巡检模型、推理程度、档位、接口及配置版本的证据，业务筛选不会修改巡检策略或实际路由。
- 建议份额包含待评估账号的中性探索份额，不等于实际路由百分比。

## 实际自动调度

分组卡片页默认每 10 秒静默刷新当前平台筛选下已展开分组的当前分页，更新缓存、评分、账号状态、权重及容量，不清空原列表，保留分页、折叠、筛选和勾选。页头可选择 5/10/15/30 秒或关闭，设置保存在浏览器；巡检进度每 5 秒查询，巡检过程中也刷新账号数据。后台标签页、弹窗、提交操作或已有请求未完成时暂停，返回可见页面立即补刷。刷新只读取已有数据，不发起新的付费检测。

自动模式按分组 + 请求模型 + 推理程度 + 服务档位 + 接口精确匹配。推理程度未明确传递时，只匹配 `unspecified`。非匹配请求继续原有调度；图片/压缩等其他接口不会被误当成普通文本接口。

采用原子快照供请求热路径读取，缺失或超过两分钟未更新时回退原生调度。自动模式下，一次近期明确的糖果 incorrect 或上下文矛盾即把质量乘数降至最低 0.1，无需等待三个样本，也不受质量评分项权重影响；证据落库后立即刷新路由快照，不等待定时周期。检测异常不代表降智，也不会清除最近一小时内尚未被有效通过结果替代的降智证据。能力评分本身仍需三个有效样本。其他乘数调整（包括恢复）每分钟最多变化 0.15，范围 0.1–2；未知账号从中性值开始。候选内保留 5% 均匀探索份额。OpenAI 新调度与通用/旧调度均有接入，不会只改变列表排序。

健康会话继续粘连，已确认的近期能力异常可逃逸普通会话粘连；不能移动的 previous_response/tool/guardian 绑定继续保护上下文一致性。并发、额度、模型能力、分组限制等仍由原有准入代码执行，不覆盖账号全局优先级。关闭自动模式会清除本机该组的质量快照，其他节点在其刷新周期内退出。

“调度诊断”显示条件匹配结果、生效乘数和近期选取记录。事件是本节点内存记录（最多 512 条，显示最新 100 条），重启清空；不是永久审计库，也不等于完整调用链。

## 预算、恢复与部署

每轮先原子预留：糖果 1 个远端任务额度、指纹最多 3 次、上下文最多 3 次；全部开启最多 7 个额度/账号。参数预检失败不消耗额度，提交尝试按一个额度保守计数；轮询/取消不计额度。完成轮次按已消耗额度释放剩余预留，异常取消轮次保守保留预留。按北京时间日界线计算预算，跨午夜旧轮次停止，避免占用新一天未预留额度。预算不足暂停到次日；账号上限按最久未测优先轮换。

数据库租约防止跨进程重复轮次；过期轮次标为 interrupted，取消/过期任务无法继续写入或复活。重启后重新加载策略、参考库和渐进乘数，不重放已完成题目；未完成轮次保留异常状态供查看。

数据库迁移：246 新增策略/任务/结果表；247 新增指纹证据、协议、请求计数和独立组内权重表；248 新增错误条件字段；249 是旧中转方案已执行的迁移，保留文件及空闲表用于兼容，检测流程不再读取或写入这些表。原始账号凭据、余额与全局优先级不变。

备份：

- 第一阶段前：`C:\sub2api-local\backups\before-account-quality.dump` 与 `sub2api-before-quality.exe`。
- 完整版前：`C:\sub2api-local\backups\before-quality-complete-20261019.dump` 与 `sub2api-before-quality-complete-20261019.exe`。
- 恢复旧程序可忽略新增独立表；不要随意回滚数据库覆盖后来用户产生的记录。
